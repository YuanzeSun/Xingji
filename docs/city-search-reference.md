# 城市归属与收藏检索

本轮以城市为主要入口，不提供座位号或资料来源检索。当前数据结构直接调整，不维护早期开发版兼容。

## 数据来源与口径

- 铁路：[12306公开站点表](https://kyfw.12306.cn/otn/resources/js/framework/station_name.js)。2026-11-15快照包含3,407条有城市字段的站点记录。提取站名、原表城市字段、铁路电报码、全拼和首字母，不执行下载的JavaScript。
- 航空：[OurAirports公共数据](https://ourairports.com/data/)，[数据发布说明](https://ourairports.com/about.html)。快照提取8,693条同时具备IATA代码与市镇名的记录，包括可识别的历史机场；保留国家和地区用于同名市镇消歧。数据属于Public Domain。数据库记录数不等于当前运营机场数。
- 原始快照不包含个人行程。生成文件为 `src/data/location-reference.js`，普通构建只使用这份已审核的本地快照。运行 `pnpm update:locations` 才会主动联网更新，更新脚本在写入前检查字段、数据量和关键样本。

## 匹配规则

1. 票据明确填写的 `originCity` / `destinationCity` 优先，允许为历史站名或个人收藏口径指定城市；保存在备份和私有同步中。
2. 铁路按完整站名或电报码/全拼的明确映射匹配。不会简单截取“北京”“上海”等前缀。例如清河归北京，清河城、清河西归邢台；虎门归东莞。仅凭首字母无法唯一确定城市时不猜测。
3. 航空使用IATA代码或数据库中的明确名称；对上游没有中文关键词的北京大兴、成都天府、广州白云补充了明确名称与代码的对应，城市仍取自数据库。机场市镇字段的括号内分区说明在生成时去除，再对明确的中国城市拼音做中文归一；不能确认中文归属时保留待补充。同名海外市镇跨地区时附加地区代码，避免混成一个城市。
4. 航空市镇是数据库地理口径，可能不同于旅客习惯使用的都会区名称，例如成田与东京、纽瓦克与纽约。可在票据中明确指定希望采用的城市；不把服务都市圈当作已经核实的行政归属。
5. 名称和代码对应不同城市、重名跨城市、未收录历史名称时，自动城市为空并提示待确认，提供“城市待补充”筛选。空值不会被自动填成站名。

城市条件按归一后的城市精确匹配；“涉及城市”匹配任一端，出发/到达城市对区分方向，勾选反向后匹配完整城市/地点对调。具体车站/机场关键词可作为附加条件。设置日期范围时，只有年/月的旧票按已知区间是否重叠匹配，日期全空的票不匹配；这一规则在界面说明。

完整JSON备份保留票据原始字段和人工指定城市。保存的查询条件仅存在当前设备，不写入远端票库。

## 路路通参考

参考[路路通开发者在App Store的功能说明](https://apps.apple.com/cn/app/%E8%B7%AF%E8%B7%AF%E9%80%9A%E6%97%B6%E5%88%BB%E8%A1%A8/id756812216)：离线数据、站站查询、车次查询、拼音首字母输入和定期数据更新。这些查询方式适合转化为收藏档案的城市对/地点对、历次班次关键词、同城联查和站点输入补全。

本轮采用：离线城市归属库、同城地点联查、常用城市路线、往返筛选、出发到达互换、拼音与首字母查找。数据采用上述公开来源，未复制路路通程序或专有数据库。

实时余票、正晚点和当前列车运行图依赖其他数据授权和时效；当前程序没有这些接口。历史票据的经停路线也不能由今天的运行图直接推断。本轮未将这些尚无数据依据的功能加入收藏记录。

## 验证范围

测试逐一核对当前快照中全部无歧义的站名，以及清河/清河城、同城多机场、地点与代码冲突、海外同名市镇、人工城市覆盖与备份/同步。真实应用DOM流程覆盖中文输入法、组合筛选、城市对反向、时间轴以及导出超过一页的匹配结果。尚未进行真实手机浏览器验收。
