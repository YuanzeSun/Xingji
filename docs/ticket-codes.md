# 火车票与登机牌原码

编辑票据时，可用相机扫描、上传图片，或选择“读取本次图片中的码”。识别成功后，保存原始载荷字节及编码参数；程序重新生成条码，再次解码并比较原始字节、字符编码和码制标识，一致后才接受结果。存在多个候选码时由用户选择。

票据保存的是可重建数据，不保存裁取的 PNG 或整张照片。预览、SVG、PNG 与纪念册均按保存的数据重新绘制；JSON 和私有仓库同步保留同一载荷，删除票据会清除该载荷。当前支持铁路 QR、Micro QR 和 Code128，以及登机牌 PDF417、Aztec、QR、Data Matrix、Code128。旧红票的 Code128 按原码重绘，行程字段可继续通过扫描票面或手动填写。

## 内容与生成能力调研

2026-11-17 核对公开规范和现有实现。需区分三个动作：从已知字节绘制图案、解释字节的业务含义，以及只凭票面字段还原完整原码。

| 类型 | 可确认的内容与边界 | 能否仅凭录入信息还原 |
| --- | --- | --- |
| 铁路票号、订单号及底部售票码 | 属于售票业务标识；12306 长票号与乘客关联。不同票据年代、票种应分别核对，本次未找到可用于完整生成的铁路公开编码规范。 | 不能从车次、日期、姓名等行程字段确定原业务编号；保留原票输入或识别结果。 |
| 铁路纸票二维码 | 行迹可识别旧式 144 位铁路纸票二维码中的主要票面字段，包括实名票的旅客姓名和证件号。 | 已收录的原码按原始字节重绘。没有原码时，可用足够且能无损表示的票面字段重建同格式的二维码。 |
| 航空电子票号、PNR、值机序号 | 电子票号通常为 13 位，PNR 是订座记录的定位标识，值机序号由值机流程分配；它们与航班号不同。部分编号有可计算的校验部分，仍不能据此推导系统分配的完整真实编号。 | 不能只由姓名、日期和航线算出原编号。 |
| IATA BCBP 登机牌二维条码 | 标准化内容包括旅客姓名、PNR、起降机场、实际承运航司／航班、飞行日序、舱等、座位、值机序号及旅客状态；还允许票号、行李、常旅客、航司自定义数据和安全签名。PDF417、Aztec、QR、Data Matrix 是不同的图案载体，不代表内容格式各不相同。 | 数据完整时可以编码成符合格式的条码；仅有姓名、航班、日期等部分字段，无法恢复遗漏的编号、自定义内容或签名。 |
| 航司旧式一维条码 | 不能只凭外观认定为 BCBP；其业务载荷需按实际码制、航司和年代核对。 | 保存原始载荷后可以按支持的码制重建；未验证业务格式时不按通用模板编造。 |

BCBP 的标准飞行日期使用年内日序，读取旧票时需另行确认年份；不能把当前年份自动套到历史登机牌。标准基础字段也不能保证提供起飞时刻、登机时刻、登机口或机型，这些信息仍需从票面或其他来源补充。IATA 明确区分舱等与订座子舱位，解析时不能混用。

IATA 的安全签名是可选字段；采用签名时，必须有航司私钥才能新签名。保留原始完整字节可以保留已有签名，修改内容后不能沿用旧签名。重新画出条码只说明载荷能够编码，不代表通过航司系统校验或获得新的乘机资格。

机票编辑器先提供原码扫描与图片读取，解码后带入姓名、PNR、机场、航班和座位等可确认字段；年份不从年内日序推断。扫描原码后，末尾的条码补充字段置灰，网页版移除原码后可继续填写。原码保留完整载荷，票面与原码的差异仅提示核对。

## 从填写信息生成

火车票在没有录入条码时，可以用起讫站、车次、出发日期和时间、席别、票价及完整底部售票码生成旧式铁路二维码。实名票还需要姓名及完整居民身份证号。二维码包含完整证件号，票面仍按原样遮挡证件号。生成的码跟随票据字段显示和导出，已有原码优先。生成码保存可重建的票面信息，历史原码的附加位及确切载荷仍需从原票收录。

机票编辑器末尾提供条码补充字段。支持 PDF417、Aztec、QR Code 和 Data Matrix。姓名按英文“姓/名”填写，超长姓名需按原登机牌缩写，不静默截断；起降机场使用三字代码；代码共享航班需核对实际承运航司及航班。条码复用票面上的舱位代码和其他已有信息，补齐值机序号、打印时的旅客状态等蓝色星号字段即可生成。

| 字段 | 编码长度 | 处理方式 |
| --- | --- | --- |
| 格式、航段数 | 1 + 1 | 自动为 M、1 |
| 英文姓名 | 20 | 用户确认，右补空格 |
| 电子客票标记 | 1 | 默认 E，也可选空白 |
| 实际承运航司的 PNR | 7 | 用户填写／确认，右补空格 |
| 出发及到达机场 | 3 + 3 | 使用机场代码 |
| 实际承运航司代码 | 3 | 二位或三位代码，右补空格 |
| 航班数字及后缀 | 5 | 数字前补零至四位，后一位为字母或空格 |
| 飞行日期 | 3 | 从完整日期自动换算年内日序，含闰年处理 |
| BCBP 舱等 | 1 | 独立选择，不从订座子舱位猜测 |
| 座位 | 4 | 数字座位补零，INF 等字母代码补空格 |
| 值机序号 | 5 | 用户填写，数字补零，字母数字代码补空格 |
| 打印时旅客状态 | 1 | 用户明确填写或从原码读取，1 表示已值机；不随事后登机状态改变 |
| 附加字段长度 | 2 | 基础生成自动为 00 |

基础载荷共 60 个 ASCII 字符。13 位电子票号、证件号、票价、登机口和起飞时刻不是该基础块的生成必需数据；航司附加字段及安全签名不生成。字段齐全且有效时，系统自动生成条码。修改相关字段会自动更新条码。缺少条码所需信息时，可以按票据本身的必填规则保存；本工具先前生成的条码会清除。已生成的基础码可在再次编辑时带回补充字段。扫描取得的原码始终优先。单航段基础字段宽度另与[独立 BCBP 解码器的字段定义](https://github.com/ahmethasmerdogan/bcbp/blob/main/README.md#the-field-layout)交叉核对；四种码制均使用独立 ZXing 解码验证完整载荷。
