# 字段录入与实时扫描

当前是开发版，直接使用现行结构。默认录入方式为字段表单；图片、文件及粘贴文字作为其他输入方式。界面使用功能名称，保留必要的操作状态与错误信息，不使用抒情标题或重复的限制说明。

## 字段表单

支持火车票/机票切换、路线、班次、日期时间、旅客、席位、人民币票价；展开后可填城市、站点代码、票号、机场登机信息。表单直接保存，也可进入带票面预览的完整编辑器。页面内切换会保留未保存的输入，实际保存成功后才清空草稿。

## 相机流程

1. 用户点击打开相机后，通过浏览器 `getUserMedia` 请求视频，优先选择后置镜头，不请求音频。视频使用 `playsinline` 和静音播放。
2. 按可见取景框映射相机画面，检查曝光、对比度、清晰度和帧间移动。稳定后对取景区域进行本地OCR，复用同一个识别进程。
3. 铁路票面放大并增强字迹，日期定位后单独识别年月日；只在确实识别到年月标签时解析局部日期，不从一串杂乱数字猜日期。车站拼音仅在数据库名称无歧义时转换为站名。
4. 登机牌保留字形细节，按一张票面处理主券/副联的重复字段，识别明确的机场代码对；有清晰标签时区分登机时间和起飞时间。
5. 至少连续两次读取的主要字段一致，自动截取当前图像并进入校对。日期等字段不完整时，明确读到班次与起终点也可进入表单补充。最后由用户保存，不自动写入票库。
6. 关闭扫描、切后台、相机中断、识别完成时释放视频轨道与识别进程。相机授权或初始化在关闭后才返回，也会立即释放。重试由用户触发。

扫描原图留在本次校对内，可以直接选择“从本次扫描图裁取”收录二维码。整张图和连续视频不进入档案或远端数据仓库。

## 验证

自动检查覆盖画面质量、移动重置、识别结果一致性、日期局部读取、站名拼音、登机牌重复字段、权限拒绝、切后台、关闭后迟到的相机资源，以及表单保存与草稿保留。

Chromium实测使用虚构票据生成的Y4M视频作为相机源，经过真正的浏览器相机API和Tesseract流程：火车票G7602、2018-10-01、杭州东至南京南；机票MU5403、2025-05-03、SHA至TFU。两者均自动进入校对，完成后视频轨道为 `ended`。另检查1440px桌面与390px手机宽度布局。这里的手机宽度检查属于浏览器模拟，iPhone和安卓真实摄像头仍需设备验收。

API参考：[MediaDevices.getUserMedia](https://developer.mozilla.org/en-US/docs/Web/API/MediaDevices/getUserMedia)、[MediaStreamTrack.stop](https://developer.mozilla.org/en-US/docs/Web/API/MediaStreamTrack/stop)、[Tesseract.js](https://github.com/naptha/tesseract.js/blob/master/docs/api.md)。
