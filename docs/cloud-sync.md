# GitHub云同步与一致性

本版本必须连接GitHub私有仓库。静态网页由GitHub Pages托管，设备直接调用GitHub Git Database API，不需要本机常开服务。私有仓库保存票据JSON与主动收录的二维码，当前浏览器的IndexedDB保存缓存和最近确认的共同版本。

飞常准MCP Key保存在私有仓库 `archive/index.json` 的 `settings.flightMcpKey` 中，与票据变动在同一提交发布。本机同时用事务保存连接设置及其共同版本，参与待确认状态、并发合并、响应丢失重试和冲突选择。冲突界面只显示Key尾号，不暴露完整Key。Key在此仓库及Git历史中为明文，但不进入常规票据备份或票面导出。GitHub访问凭证不共享。

“保存并同步”只保存设置；任何设备收到Key、启动、回到前台或重试同步时，都不会调用飞常准。只有选择年份并点击“查询历史行程”才调用 queryUserHistoryTrip 查询该年份的本人历史航班，每次只查一个年份。

飞常准查询仅在电脑端显示。Chrome或Edge安装“行迹 · 飞常准连接”扩展后，网页直接调用飞常准，无需托管中转服务。扩展仅对行迹站点访问指定MCP接口的请求补充响应头读取及预检声明，没有后台脚本，不读取或保存Key。安装包可从“数据与同步”下载。

## 连接与断联

- 首次使用必须验证私有仓库、读写权限并完成同步。已初始化README的空票库会在首次同步中创建完整性索引。
- 每台设备绑定仓库数字ID和具体分支。退出授权保留绑定，不能用另一个仓库覆盖现有缓存；仓库身份变化会停止同步。
- 断网、授权失效、同步异常或未处理冲突时只读。查看、检索、时间轴和导出仍可使用；录入、修改、删除和扫描需要先恢复连接。
- 打开应用、回到前台、点击同步和保存时核对云端；前台正常连接时约30秒检查一次。关闭应用后不承诺后台同步。

## 保存与确认

1. 保存前从云端核对最新版本，失败则保留当前输入，不提交修改。
2. 以一笔本机事务合并其他标签页刚提交的修改，并同时保存票据和待确认状态。
3. 读取同一云端提交中的全部年份文件及索引，核对文件集合、SHA-256、记录数量和ID唯一性。
4. 以最近共同版本、本机版本、远端版本做三方合并。不同字段的修改可同时保留；同一字段有不同修改时停止写入，展示双方值供选择。选择会绑定当时的冲突内容；远端再次变化后旧选择不会自动套用。
5. 用单个Git树和提交发布全部年份变动、删除标记与索引。更新分支使用 `force: false`，竞争失败后重读合并，至多立即重试3次，然后退避重试。GitHub的非强制分支更新要求快进，见 [GitHub官方接口说明](https://docs.github.com/en/rest/git/refs#update-a-reference)。
6. GitHub确认后再用本机事务更新已确认基线、提交号和同步时间。期间发生的其他本机修改重新合并；过期的同步响应不能覆盖较新的已确认版本。

上传时断线，可能意味着GitHub已写入而设备没有收到确认。应用保留待确认内容并只读，重新连接后读取云端比对，避免重复创建票据。只有云端提交和本机确认完成才显示“已同步”。“上次同步”表示最后成功核对时间，不代表设备在断网时仍掌握其他设备的最新修改。

## 重复、删除和异常

- 不同来源或不同设备录入同一票据时，用票据身份规则统一ID和合并ID，并在存储层合并。人工字段出现无法自动决定的不同内容时需要选择。
- 删除清空票面字段、来源和二维码，保留必要ID及合并ID删除标记。旧设备或旧备份不能让记录自动复活；删除与另一设备编辑冲突时由用户决定。不提供回收站。
- 年份文件缺失、完整性校验失败、索引丢失、仓库身份变化、分支回退或分叉时停止写入，保留本机缓存。分支历史通过 [GitHub提交比较接口](https://docs.github.com/en/rest/commits/commits#compare-two-commits) 核对；不会强行重写远端历史。
- SHA-256索引用于发现不完整或被意外修改的快照，不提供端到端加密或对拥有仓库写权限者的防篡改保证。
- 多设备是同步后收敛，设备之间有可见延迟。没有用设备时钟决定覆盖顺序，也不宣称随时全局实时一致。

自动补全来源跟随对应字段参与合并，手动校正不会被刷新结果静默覆盖。生成条码在票面字段合并后重新计算；原码、来源与实际承运航班覆盖信息整体处理，真实冲突仍需明确选择。新增来源信息包含在 JSON 和私有仓库数据中，删除票据时清除。

## 验证范围

`tests/cloud-consistency.test.js` 使用内存GitHub API模拟两设备同时提交、分支竞争、确认响应丢失、文件损坏、分支回退、本机标签页并发、同步过程中新增修改和本机事务回滚。`tests/cloud-policy.test.js` 检查首次连接门槛、断网只读、凭证失效、恢复连接和退出授权后保留缓存。浏览器预览使用虚构数据与隔离的模拟GitHub服务，不写入个人私有仓库。

实际Chromium中已验证手机宽度的首次连接与只读页面、上传确认响应丢失后的重试、两标签页同时修改不同字段后保留双方内容，以及完全断网后由PWA缓存重新打开应用并只读查看票据。
